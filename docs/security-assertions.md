# Security assertions — the claim → assertion matrix

*ST-6.4. `docs/threat-model.md` and the README's security table each make
claims; this file maps every load-bearing claim to the suite assertion that
checks it, and names the claims nothing checks. Without it, "the suites are
green" is unfalsifiable: a matrix row that says UNCHECKED is visible as
unchecked, which is the only way an unchecked claim stays honest.*

Generated by ST-6.4 against the security suites (dev/accept-security-*.sh),
the unit/property tests, and the audit. Claims are grouped by the threat they
answer. A row's "checked by" names the suite file and, where useful, the
assertion's subject.

## The gap this matrix is for

The UNCHECKED rows are the work the plan's Phases 2–4 proposed: the
controlled-origin battery (D90), session-end signing (D93's open half), the
SBOM scan tooling (D89-adjacent). They are visible here as unchecked on
purpose — the alternative is a green suite list that quietly means nothing
about the claims nobody wrote an assertion for.
